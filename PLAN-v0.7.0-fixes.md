## Дополнение (2026-09-10, вечер): видимость статуса для пользователя

Запрос владельца: пользователь должен **видеть**, что модель работает по списку,
что напоминания работают и что список восстановлен после обрыва/выключения/
компрессии. Разбор показал: для модели всё это работает (доказано логами 09:32/
11:03), но для пользователя видимость ломает сам хост — панель тодо питается от
turn-local проекции `todos` (`dsh-tool-todo/lib/index.js`: fold возвращает `null`
на каждом `turn/start`; зеркало — `backscanTodos` в `dsh-client-connection`), поэтому
после resume панель пуста до следующего `todo_write` модели.

Сделано:

1. **UPSTREAM.md** — новое предложение «The UI pays the same tax»: проекция
   `todos` для UI должна быть долговечной (last-write-wins по всему логу);
   приведены точные места в хосте и утренний таймлайн как доказательство.
2. **Чип «Todo Gate»** (client.js) — постоянный индикатор в слоте
   `conversation.input.left` рядом с композером: счётчики списка, простой в ходах,
   последнее действие плагина (`reminded` / `restored after compaction` /
   `restored after resume` / `gate sent the turn back`) со временем. Данные —
   долговечный backscan хвоста `session.history` (сознательно игнорирует
   `turn/start`, в отличие от панели); restore-детект — по формулировке подписи
   («compaction») либо по паузе ≥ 3 минут перед границей хода (shutdown/resume).
   Только чтение, fail-open (любая ошибка прячет чип). Контракты спайка:
   слот-паттерн по образцу чипа plan-режима (`dsh-client-ui-plan`), props
   `sessionId` из `inject(sessionId)`, системная `useProjection`, провод
   `session.history`; `immediately: true` в `dsh.client` — материализация на
   старте приложения.
3. **Тесты**: 9 новых (84/84) — долговечный backscan, idle-подсчёт,
   классификация доставок, restore-детект (компакция/resume/не-restore/veto),
   текст чипа; клиентский модуль грузится в node через window-шим.
4. **verify-live**: проверка D (P1) уточнена по живому случаю 0d23a151 11:02 —
   компакция → модель сама перезаписала список первым ходом → hand-back доехал
   на результате этой записи. Честный инвариант — «план дошёл до модели до конца
   хода»: доставкой **или** собственной перезаписью модели; формулировка
   «hand-back строго до следующей записи» была слишком строгой и дала ложную
   тревогу. verify:live и strict — PASS.

Верификация волны: `npm run verify` 84/84, `types` зелёный, `--selftest` PASS,
`verify:live` PASS, `verify:live:strict` PASS. Ручной шаг человека: обновить
страницу GUI (или рестарт хоста) и убедиться, что чип виден над композером.
