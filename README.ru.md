# dsh-todo-continuation

[English](README.md) | [Русский](README.ru.md) | [简体中文](README.zh.md)

Плагин для DeepSeek Harness (DSH), реализующий шлюз остановки на основе Todo-списка
и одну рекомендательную подсказку. На границе `agent/turn-stopping` читает текущий
слепок `todo/write` и решает, можно ли завершить turn, а также напоминает модели,
когда уже существующий список давно не обновлялся. Модель сама решает, когда
заводить todo-список, — плагин не подталкивает её к планированию; но если список
создан, плагин не даёт его забросить. Интервал и текст подсказки настраиваются в
веб-интерфейсе (Settings) и вступают в силу на следующем же turn.

> Часть коллекции [dsh-plugins](https://github.com/DoiiarX/dsh-plugins) —
> полный указатель самодельных плагинов см. в том репозитории.

## Как проверить, что он работает (2 минуты)

1. Перезапусти DSH — процесс держит старую версию плагина в памяти, без рестарта
   ничего нового не появится.
2. Открой **Настройки → Todo Gate** и включи **Log every decision** (остальное можно
   не трогать).
3. В чате напиши: «Составь todo-список из трёх пунктов для задачи X. Отметь
   выполненным только первый. Больше ничего не делай».
4. Вот что должно произойти — и что это значит:
   - модель не даёт ходу закончиться и получает сообщение про незавершённые пункты —
     это **шлюз остановки**;
   - когда контекст сжимается (или список несколько ходов не трогают), модели
     приходит «Automated note: …» вместе с самим списком — это **напоминание**;
   - в журнале хоста на каждое решение есть строка
     `[todo-continuation] … at=stop-boundary …` с причиной: `prompt:…`, `skip:…` или
     `gate:…`. Строки нет — плагин не смонтирован; строка есть — видно, почему молчал.
5. Надоело — поставь **Stale-todo prompt interval** = 0 и **Stop-gate vetoes per
   turn** = 0: напоминаний и вето больше не будет.

Автоматическая проверка по реальным журналам (не нужны ни модель, ни чат):

    node test/verify-live.mjs --since "2026-09-09T11:05:00"

читает твои `~/.dsh/sessions`, считает доставленные напоминания, вето и компакции и
проверяет контракт на событиях после указанного момента; `--explain` печатает решение
по каждому ходу, `--id <часть-id>` ограничивает одной сессией.

## Все настройки (Настройки → Todo Gate)

| Поле | По умолчанию | Что делает |
| --- | --- | --- |
| Stale-todo prompt interval | 5 | напомнить о списке, если его столько ходов не обновляли; 0 = выкл |
| Stop-gate vetoes per turn | 2 | сколько раз за ход не давать остановиться при незавершённых пунктах; 0 = выкл; максимум 10 |
| Gate subagents too | вкл | распространить вето на сабагентов |
| Hand the list back after a compaction | вкл | вернуть список сразу после сжатия контекста |
| Post-compaction prompt text | встроенный | текст возврата после сжатия |
| Stale-todo prompt text | встроенный | текст напоминания (обязателен `{n}`) |
| Log every decision | выкл | одна строка в логе на каждое решение плагина |
| Per-list reminder cap | 0 | после N напоминаний про один неизменённый список замолчать до его перезаписи; 0 = напоминать всегда |

## Возможности

1. **Шлюз остановки (с лимитом)**: пока в текущем turn есть незавершённые todo,
   turn не может завершиться — заблокированная попытка получает сообщение-
   продолжение, и модель продолжает работу в том же turn. Начиная с v0.2.0
   **исключений по маркерам нет**: todo, начинающееся с `[WAITING_USER]`,
   `[INFO_NEEDED]` или любого другого префикса, всё равно незавершённое и всё
   равно блокирует остановку. Остановка разрешена, когда в слепке текущего turn
   все todo завершены, — либо когда turn израсходовал свой бюджет вето
   `gateMaxSteersPerTurn` (v0.5.0). Именно лимит не даёт списку, который модель
   не может доделать, крутить turn бесконечно: без него одна граница остановки
   может быть заблокирована сотни раз внутри одного turn.
2. **Подсказка «устаревший Todo»** (рекомендательная): когда **действующий**
   список todo сессии — последний `todo/write` в durable-журнале сессии — всё
   ещё содержит незавершённые пункты и не перезаписывался
   `staleTodoPromptEveryNTurns` (по умолчанию 5) turn, плагин вставляет
   подсказку **вместе с самим списком**, чтобы модель могла подхватить план
   после компакции, возобновления сессии или рестарта хоста. `{n}` — фактическое
   число пустующих turn. `0` выключает её.
3. **Возврат списка после компакции** (v0.6.0): запись `compaction/summary` в
   журнале сессии означает, что модель только что потеряла ту копию плана, по которой
   работала. Если в стоящем списке есть незавершённые пункты, список возвращается
   сразу, не дожидаясь интервала. По одному напоминанию на `compactionId`; неудачная
   компакция (summary так и не записан) триггером не является.
4. **Доставка в середине хода** (v0.6.0): то же напоминание добавляется к следующему
   результату инструмента как дополнительный контекст, поэтому больше не зависит от
   того, дойдёт ли ход до границы остановки. Ходы, умирающие на ошибке провайдера
   (429), на отмене или на сообщении, набранном, пока ход ещё открыт, до этой границы
   не доходят — именно поэтому напоминание только на границе могло молчать целыми
   сессиями. Канал в середине хода только добавляет контекст: вето он не накладывает,
   а любая своя ошибка в нём отдаёт принятое решение инструмента нетронутым.
5. **Видимые уведомления** (v0.6.0): каждая инъекция объявляется как `notice` с
   однострочной подписью, поэтому веб-клиент показывает её в транскрипте свёрнутой
   строкой («todo-continuation: …») — работа плагина видна не только модели, но и тебе.
6. **Лимит на один список — опционален** (v0.6.0): по умолчанию напоминание
   повторяется каждый интервал, пока список стоит неизменным, — как в оригинале.
   Если шум надоест, поставь «Per-list reminder cap»: после N напоминаний про один
   и тот же список плагин замолчит до перезаписи списка или новой компакции
   (переход в тихий режим отмечается в журнале один раз уровнем `info`, а не `debug`).

Простой считается по журналу сессии в момент проверки, а не по тому, что плагин
успел увидеть в этом процессе: возобновлённая после рестарта сессия оценивается
так же, как не прерывавшаяся. (До v0.5.0 ответ на вопрос «есть ли список» брался
из счётчика в памяти, который обнулялся при каждом рестарте, из-за чего в реальных
сессиях подсказка почти никогда не срабатывала.) В памяти остаются только
кулдаун подсказок и счётчик вето текущего turn, и их потеря стоит максимум
одного лишнего напоминания.

Плагин никогда не создаёт, не удаляет, не завершает и не перезаписывает todo —
единственным автором списка остаётся модель, и он не подталкивает модель к
планированию: сессия без единого `todo/write` не получает подсказок вовсе
(no-todo advisory удалён в v0.4.0), как и список, в котором все пункты завершены
— восстанавливать нечего. Подсказка рекомендательная (сама по себе завершение не
блокирует) и срабатывает не чаще одного раза за интервал, чтобы не докучать
модели на каждом turn.

## Инвариант шлюза остановки

> На каждом событии `agent/turn-stopping` шлюз либо находит ноль незавершённых
> todo в слепке `todo/write` текущего turn, либо вставляет steer-продолжение —
> пока у turn не исчерпается бюджет вето (`gateMaxSteersPerTurn`, 0 = шлюз
> никогда не блокирует), после чего остановка разрешается, а достижение лимита
> попадает в лог. Шлюз не
> бросает исключений, не действует поверх отмены пользователем (abort проходит
> мимо границы остановки по построению) и читает только todo своей сессии.

Когда шлюз блокирует остановку, модель получает указание: либо доделать todo,
либо задать вопрос через `ask_user_question` — ожидающий вопрос ставит turn
на паузу *внутри* текущего шага, поэтому шлюз на неё не срабатывает. Сабагентам
(runtime-owned) задавать вопросы запрещено (`DELEGATED_CALLER`) — заблокированный
сабагент должен включить нерешённый вопрос в свой финальный результат. Отмена
пользователем остаётся жёстким выходом: отмена никогда не проходит через шлюз.

## Состав

- `index.js` (host): регистрирует namespace настроек `todo-continuation` и
  реализует ограниченный шлюз остановки плюс подсказку о стоящем списке, которую он
  выводит из журнала сессии; доставка идёт на `agent/turn-stopping` **и** в середине
  хода через дополнительные контексты `tools/post-execute`. Внешних зависимостей нет;
  `schemastery` импортируется динамически в `apply()`, и любой сбой откатывается к
  встроенным значениям по умолчанию — громко, потому что молча деградировавший
  интервал неотличим от плагина, который ничего не делает.
- `client.js` (browser): рисует раздел «Todo Gate» на странице настроек — интервал,
  лимит вето, переключатель «вернуть список после компакции» и его текст, текст подсказки про
  устаревший список и переключатель журнала решений — плюс постоянно видимый чип
  статуса в строке ввода разговора (см. «Чип статуса»).
- `cordis.patch.yml`: объявляет строку плагина `dsh-todo-continuation`.
- `package.json`: манифест `@doiiarx/dsh-todo-continuation` с `dsh.client`
  инъекцией и зависимостью `schemastery`.

## Установка

Установите зависимости в каталоге плагина (host-сторона делает
`import('schemastery')` в `index.js`):

```sh
cd <каталог-плагина>
pnpm install
```

### 1. Подключение в web-профиль

В `$HOME/.dsh/profiles/web/package.json`:

```json
{
  "dependencies": {
    "@doiiarx/dsh-todo-continuation": "github:zhihus/dsh-todo-continuation-en"
  },
  "dsh": {
    "profile": {
      "bundles": [
        "@doiiarx/dsh-todo-continuation"
      ]
    }
  }
}
```

Затем выполните `pnpm install` в каталоге профиля.

### 2. Открытие namespace для браузерной страницы настроек

Браузерная страница настроек сможет прочитать namespace `todo-continuation`
только если он добавлен в белый список `WEB_SETTINGS_NAMESPACES` в apiproxy
(`packages/host/apiproxy/src/api-proxy.ts`); иначе страница будет показывать
«Loading configuration…» (namespace не открыт для клиента).

```ts
const WEB_SETTINGS_NAMESPACES = [
  'agent-loop', 'shell', 'locale', 'permission', 'ui-conversation', 'ui-theme', 'web-search-deepseek',
  // ...namespace локальных плагинов...
  'todo-continuation',
] as const
```

После этого пересоберите apiproxy (`pnpm run build:lib:host`) и перезапустите
web-процесс.

> **Примечание**: в установленной версии DSH 0.1.1-rc.2 (npm) жёсткий белый
> список отсутствует — apiproxy динамически отдаёт все зарегистрированные
> namespace через `settings.describe()`. Шаг 2 может не потребоваться.

## Конфигурация

Редактируется в секции «Todo Gate» на странице настроек:

| Поле | По умолчанию | Значение |
| --- | --- | --- |
| `staleTodoPromptEveryNTurns` | 5 | сколько ходов стоящий список может не обновляться, прежде чем модель получит его обратно; 0 = выключено. Список, простоявший больше 20 × интервала, — брошенная работа: интервальное напоминание прекращается само (`skip:too-old`), но компакция по-прежнему возвращает список |
| `gateMaxSteersPerTurn` | 2 | сколько раз один ход можно отправить обратно из-за незавершённых пунктов, прежде чем остановка станет разрешена; 0 = шлюз не накладывает вето; ограничен сверху значением 10 |
| `gateSubagents` | true | распространяется ли вето на делегированные (сабагентные) сессии; с `false` ребёнка не отправляют обратно, но список ему по-прежнему отдают как контекст |
| `maxPromptsPerList` | 0 (без лимита) | после стольких подсказок об одном неизменном списке плагин замолкает о нём, пока список не перепишут или не приземлится новая компакция; вход в тишину отмечается один раз уровнем `info` |
| `promptAfterCompaction` | true | вернуть список сразу после приземлившейся компакции, не дожидаясь интервала |
| `compactionPromptTemplate` | встроенный текст | текст возврата после компакции; ни один placeholder не обязателен |
| `staleTodoPromptTemplate` | встроенный текст | текст подсказки об устаревшем списке; обязан содержать `{n}` |
| `logDecisions` | false | писать в журнал хоста по одной строке на границу и на результат инструмента: что плагин сделал или почему промолчал |

Восемь полей на странице настроек подписаны **«Stale-todo prompt interval»**,
**«Stop-gate vetoes per turn»**, **«Gate subagents too»**, **«Hand the list back after
a compaction»**, **«Post-compaction prompt text»**, **«Stale-todo prompt text»**,
**«Per-list reminder cap»** и **«Log every decision»**.

Пороги читаются из settings-документа вживую: сохранённое на странице настроек
значение меняет поведение уже на следующей границе остановки, без рестарта.
Значения можно зафиксировать и на уровне composition (bundle config, слой
`base`), который пользовательский слой настроек перекрывает.

## Что пишет журнал решений

С включённым `logDecisions` каждая граница и каждый результат инструмента дают
одну строку:

```
[todo-continuation] session "…" turn 12 at=stop-boundary skip:idle 2<5
[todo-continuation] session "…" turn 12 at=mid-tool-result prompt:compaction id=9458… idle=1
[todo-continuation] session "…" turn 12 at=stop-boundary gate:block unfinished=1/3 vetoes=1/2
[todo-continuation] session "…" turn 12 at=stop-boundary gate:cap-reached unfinished=1 vetoes=2/2 allow-stop
```

Причины такие: `prompt:compaction`, `prompt:stale`, `gate:block`,
`gate:cap-reached`, `gate:off`, `gate:allow`, `gate:skipped subagent` и пропуски
`no-list`, `no-unfinished`, `interval-off`, `no-write-turn`, `idle N<cfg`,
`cooldown N<cfg`, `too-old idle N` (горизонт брошенной работы), `quiet` (кап по
списку выше). Это и есть
разница между «плагин умер» и «ничего не было по расписанию», которую иначе
приходится устанавливать по сжатому журналу сессии.

## Чип статуса

Панель тодо в хосте следует turn-local проекции `todos` и гаснет на каждом
`turn/start` (и остаётся пустой после рестарта приложения до следующего
`todo_write` модели — почему это дыра хоста, см. `UPSTREAM.md`). У плагина есть
свой всегда видимый ответ: **чип «Todo Gate»** в строке ввода разговора, рядом с
композером.

Чип показывает для активной сессии:

- счётчики стоящего списка — `2/3 unfinished` (не выполнено) или `3/3 done`,
  когда всё завершено;
- простой в ходах (`idle 1t`) — сколько границ хода прошло с последней
  перезаписи списка;
- последнее действие плагина — `reminded 10:38` (напомнил), `restored after
  compaction 11:03` (вернул после компакции), `restored after resume 09:32`
  (вернул после возобновления) или `gate sent the turn back 10:37` (гейт
  отправил ход назад).

«Restored» — видимая работа петли восстановления: возврат после компакции
определяется по формулировке подписи, а напоминание, пришедшее в ход, открытый
после долгой тишины (пауза при выключении/возобновлении от 3 минут), — как
возврат после resume. Чип выводит всё это из долговечного хвоста журнала сессии
через публичный провод `session.history` — долговечный backscan, сознательно
игнорирующий `turn/start`, в отличие от панели. Он только читает и отказывает
открыто: любая ошибка чтения или разбора просто прячет чип и никогда не мешает
разговору. Точечная правка самой панели описана в `UPSTREAM.md`.

## Шаблон подсказки (контракт placeholder)

У stale advisory один редактируемый шаблон. Его дефолт велит модели сделать один
конкретный шаг по самому старому незавершённому пункту либо переписать/очистить
список, который больше не соответствует работе — и приносит сам список, потому
что DSH гасит действующий план на каждом `turn/start`, а в контексте после
компакции его копии может не остаться.

| Шаблон | Placeholder | Подставляемое значение | Обязателен |
| --- | --- | --- | --- |
| `staleTodoPromptTemplate` | `{n}` | ФАКТИЧЕСКОЕ число turn, которое действующий список не перезаписывался | да |
| `staleTodoPromptTemplate` | `{todos}` | действующий список, по строке `- [status] content` на пункт (не больше 30 пунктов по 200 символов) | нет |
| `staleTodoPromptTemplate` | `{total}` | число пунктов в действующем списке | нет |
| `staleTodoPromptTemplate` | `{unfinished}` | число пунктов не в статусе `completed` | нет |

Контракт:

- Подстановка буквальная: каждое вхождение placeholder заменяется его значением
  (повторные вхождения заменяются все). Никакого template engine.
- **Шаблон без `{n}` сохранить нельзя.** Это требует schema настроек
  (`Schema.string().pattern(/\{n\}/)`): страница настроек пре-валидирует черновик
  и записывает только валидный текст; любая запись через settings-инфраструктуру
  проходит через schema до персистенции. Неизвестный placeholder вида `{foo}`
  разрешён и отправляется как есть.
- Placeholder пишется ровно как `{n}` — `{ n }` (с пробелами) не матчится и
  отклоняется; `{{n}}` проходит schema и рендерится обычной literal-подстановкой
  без спец-обработки (например `{{n}}` → `{5}`).
- При интервале `0` (advisory выключен) шаблон не используется вовсе.
- Дефолтный текст изменён в v0.5.0, поэтому конфигурация, которая никогда не
  переопределяла шаблон, теперь шлёт новую формулировку вместе со списком.
- Если в `settings.yaml` оказался невалидный шаблон, schemastery отвергает его
  на регистрации, namespace не создаётся вовсе, и плагин живёт на всех встроенных
  дефолтах — с `DEGRADED` в логе хоста. Пока строку не исправят или не удалят,
  редактировать в секции «Todo Gate» будет нечего.

### Шаблон возврата после компакции

`compactionPromptTemplate` принимает те же placeholder'ы, что и шаблон устаревшего
списка — `{todos}`, `{total}`, `{unfinished}` и `{n}` (ходов с момента последней
записи списка), — но **не требует ни одного**. Обе гарантии общие: если в тексте нет
`{todos}`, отрендеренный список дописывается снизу, потому что напоминание, которое не
может показать план, — это не напоминание.

### Заметки для обновления (0.1.0 → 0.2.0)

- Маркерный протокол ожидания (`waitingTodoPrefixes`, `[INFO_NEEDED]`,
  `[WAITING_USER]`) **удалён**. Поля нет ни в схеме, ни в интерфейсе; оставшееся
  значение в пользовательском файле настроек просто игнорируется в рантайме
  (неизвестные ключи проходят через резолв schemastery) и может быть удалено.
- Дефолт подсказки «нет Todo» изменён с 5 на **0 (выключено)**. Если ваш
  пользовательский файл настроек пинит `noTodoPromptEveryNTurns`, пользовательский
  слой перекроет новый дефолт — поставьте `0` (или удалите строку), чтобы принять
  новое поведение.
- Шлюз больше не признаёт префиксы ожидания: при наличии незавершённых todo
  единственный выход для модели — доделать их или спросить через
  `ask_user_question`.

### Заметки для обновления (0.2.0 → 0.3.0)

- Тексты advisory-подсказок стали редактируемыми настройками
  (`noTodoPromptTemplate`, `staleTodoPromptTemplate`). **Мигрировать ничего не

### Заметки для обновления (0.3.0 → 0.3.1)

- Подписи на странице настроек переименованы в сторону условия срабатывания:
  «No-todo prompt interval/template» → «If there is no todo list: interval
  (turns) / prompt text»; «Stale-todo prompt interval/template» → «If the todo
  list is not updated: interval (turns) / prompt text». **Изменение только
  в интерфейсе**: ключи конфигурации, дефолты и schema не тронуты — мигрировать
  ничего не нужно.

### Заметки для обновления (0.3.1 → 0.4.0)

- **No-todo advisory удалён** вместе со своими настройками

  `todo/write` не получает подсказок вовсе. **Мигрировать ничего не нужно**:

  на странице настроек теперь **«Stale-todo prompt interval»** /
  **«Stale-todo prompt text»**.

### Заметки для обновления (0.4.0 → 0.5.0)

- **Подсказка про устаревший список пережит Рестарт.** Вопрос «есть ли у сессии
  действующий список и как давно он не трогался» теперь answered по истории
  `turn/start` / `todo/write`, а не по счётчику в памяти: возобновлённая сессия
  или рестарт хоста больше не сбрасывают плагин в состояние «здесь никогда не
  планировали» — именно поэтому в реальных сессиях напоминание почти не
  срабатывало.
- **Подсказка приносит список** через новые `{todos}` / `{total}` /
  `{unfinished}`, а `{n}` показывает фактический простой, а не настроенный
  интервал. Сохранённый вами шаблон продолжает работать как работал — просто без
  списка; очистите поле, чтобы вернуть новый дефолтный текст.
- **Завершённый список не пилится.** Подсказке нужен хотя бы один пункт не в
  статусе `completed`; очистка списка (пустой `todo_write`) тоже всё завершает.
- **Шлюз ограничен** новым `gateMaxSteersPerTurn` (по умолчанию 2, 0 = шлюз выключен).
  Поднимите его, если хотите прежний бесконечный цикл вето; логи реальных сессий
  показывают, чем он кончается (~150 вето в одном turn, больше часа токенов).
- `DEFAULT_STALE_EVERY` снижен с 20 до 5, а упавшая регистрация namespace теперь
  сообщается громко вместо молчаливой деградации.
- Мигрировать нечего: оставшийся в настройках `noTodoPromptEveryNTurns`
  игнорируется (удалите, когда удобно).

### Заметки для обновления (0.5.0 → 0.6.0)

- **У стоящего списка появились два новых триггера.** Записанная компакция возвращает
  список немедленно (`promptAfterCompaction`, по умолчанию включено, собственный
  редактируемый текст), а подсказка теперь доставляется и в середине хода как
  дополнительный контекст к результату инструмента — граница остановки больше не
  обязательна.
- **`logDecisions`** (по умолчанию выключено) печатает по одной причине на границу и
  на результат инструмента — см. раздел «Что пишет журнал решений». Включайте его,
  прежде чем сообщать о молчании плагина.
- **`gateMaxSteersPerTurn` ограничен значением 10**, а ключи настроек, удалённые в
  прежних версиях (`noTodoPromptEveryNTurns`, `noTodoPromptTemplate`,
  `waitingTodoPrefixes`), теперь называются в журнале один раз вместо тихого
  игнорирования.
- **Шаблон без `{todos}` получает список дописанным снизу**, так что отредактированное
  напоминание не может потерять план.
- **Напоминания больше не затихают сами**: лимит «2 напоминания и тишина» стал опциональной настройкой «Per-list reminder cap» (по умолчанию 0 = не затихать никогда).
- **Каждая инъекция — видимая строка-уведомление** в транскрипте (`notice` + однострочная подпись).
  Раньше игнорируемый список можно было возвращать каждый интервал до конца сессии;
  вход в тихий режим отмечается в журнале один раз уровнем `info`.
- **`gateSubagents`** (по умолчанию `true`) — вето на делегированных сессиях. Делегирование
  читается из durable-заголовка сессии (`origin`, `delegationDepth`), запасной вариант —
  событие `subagent/descriptor` в журнале; нераспознанный формат считается ходом
  верхнего уровня, поэтому отсутствующее поле не может отключить шлюз.
- **`UPSTREAM.md`** — предложение в ядро DSH: хост гасит проекцию `todos` на каждом
  `turn/start`, хотя последний снимок лежит в журнале. Именно из-за этого шлюз
  ограниченным одним ходом, а `readStandingTodos` обходит журнал.
- **Бытовуха**: `npm run verify` = проверка синтаксиса обеих сторон + полный прогон
  тестов. Плагин можно подключить как `link:<путь>` в `cordis.patch.yml` профиля вместо
  копирования в `node_modules` — тогда вопрос «а синхронизировал ли я?» не возникает.
- Миграция не нужна: существующие конфигурации продолжают работать и получают новые
  значения по умолчанию.

### Заметки для обновления (0.6.0 → 0.7.0)

- **`maxPromptsPerList` задокументирован, а напоминание больше не бесконечно.**
  Кап по списку появился в 0.6.0, но не был описан ни в одном README и по умолчанию
  был `0` (не затихать никогда — напоминать каждый интервал). Теперь он в таблице
  настроек. **Горизонт брошенной работы** ограничивает поведение по умолчанию,
  не изымая ручку: список, который модель игнорировала больше 20 ×
  `staleTodoPromptEveryNTurns` ходов подряд, интервальным каналом больше не
  возвращается (`skip:too-old idle N`); возврат после компакции — сознательное
  исключение. Горизонт — константа, а не настройка.
- **Повторная регистрация namespace больше не деградирует.** Если namespace уже
  занят другой монтировкой плагина (горячая перезагрузка, двойная строка в bundle),
  вторая монтировка читает живую регистрацию через `settings.get(ns)` вместо
  отката к встроенным значениям.
- **Граница остановки отказывает открыто (fail-open).** Баг плагина на границе
  остановки теперь изолирован так же, как баг в середине хода: сообщение об ошибке
  идёт в журнал хоста, ход завершается без вето — вместо `turn/end` с ошибкой и
  потерянного хода пользователя. Некорректная запись `todo/write` в повторно
  прочитанном журнале игнорируется, а не роняет чтение.
- **Подстановка шаблона однопроходная**: `{placeholder}` внутри авторского текста
  пункта списка больше не переписывается последующим проходом, а список не
  дублируется, когда пользовательский шаблон вставляет `{todos}` раньше остальных
  placeholder'ов.
- **Зависимость схемы переведена на форк хоста** (`@deepseek-ai/schemastery`) —
  схему настроек резолвит ровно тот код, что исполняет хост; двух расходящихся
  копий schemastery в профиле больше нет.
- **Объявлен `engines: node >=22.3`** (живой аудит использует
  `zlib.zstdDecompressSync`); `crypto.randomUUID` импортируется из `node:crypto`,
  а не предполагается.
- **Страница настроек**: поле вето ограничено хостовым потолком (10), сохранённое
  завышенное значение показывается обрезанным; недоступный namespace показывает
  явное read-only состояние вместо вечного «Loading configuration…»; мёртвая
  регистрация `__DSH_SETTINGS_SEARCH__` (в сборке хоста нет потребителя) и
  неиспользуемые инъекты `connection`/`remote` убраны.
- **Быстрее на длинных сессиях**: свёртка стоящего списка по журналу сессии стала
  инкрементальной (за проверку читаются только новые события) вместо полного
  обхода журнала на каждом результате инструмента.
- **CI и типы**: `pnpm run types` (tsc checkJs обеих сторон и тестов) и
  GitHub Actions workflow, прогоняющий `verify` + `types` + self-test аудита на
  Node 22.
- **Живой аудит (`npm run verify:live`) по умолчанию требует соблюдения контракта**:
  подсказка несёт список (A), кап по списку (B), кап вето (C), возврат после
  компакции (D) — у каждой проверки свой горизонт (для B/C/D — формулировка
  доставки), доставки классифицируются по однострочной подписи `source.summary`
  с формой сообщения как запасным вариантом, есть `--selftest`, не требующий

- Миграция не нужна: существующие конфигурации продолжают работать; задайте
  `maxPromptsPerList: 2`, если нужен самый строгий отступ, который схема
  поддерживала всегда.

## Политика релизов

Начиная со **следующего** релиза, каждый релиз помечается тегом:

1. Поднять `version` в `package.json` (semver: изменения только интерфейса или
   документации → patch, новые настройки или изменения поведения → minor).
2. Закоммитить с сообщением с префиксом `release:` и кратким описанием.
3. Поставить аннотированный тег на релизный коммит и отправить его явно:
   `git tag -a vX.Y.Z -m "vX.Y.Z: summary"`, затем `git push en vX.Y.Z` —
   обычный `git push` теги не передаёт.
4. Тег закрепляет релиз за устанавливаемым ref
   (`github:zhihus/dsh-todo-continuation-en#vX.Y.Z`) и выводит его на страницу
   GitHub Releases.

Релизы до v0.3.1 включительно версионированы только в `package.json` и тегов
не имеют.

## Примечания

- Источник сообщения шлюза — `{ kind: 'plugin', plugin: 'todo-continuation' }`,
  поэтому вставленный `user/message` можно восстановить из лога сессии.
- Отмена пользователем (`agent.cancel`) и терминальные ошибки turn прерывают
  выполнение до границы остановки и никогда не переопределяются шлюзом —
  отмена остаётся единственным выходом из turn, который модель никогда не завершает.
- Plan mode может легально завершить turn с открытыми todo; `exit_plan_mode`
  блокирует внутри вызова инструмента (ожидание пользователя), поэтому ревью
  плана шлюз не задевает. Шлюз видит только сессию исполняющего агента —
  todo-списки сабагентов для него невидимы.
- Если подключить плагин несколькими строками (например, base bundle + agent
  preset), будет зарегистрировано несколько слушателей, и на одной границе
  остановки может быть поставлено в очередь несколько сообщений; подключайте
  плагин один раз на композицию.
